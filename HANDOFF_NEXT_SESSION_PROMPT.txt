"프론트엔드 CSS/JS 규격화" 작업을 새 환경에서 이어받아 줘.

충돌·중복을 피하려고 잡아둔 범위야. 판단이 애매하면 임의로 넓히지 말고 나한테 물어봐 줘.

4. 작업할 때 지킬 것 (지금까지 실제로 데인 것들)
======================================================================
1) **옛 페이지별 CSS를 "원본 그대로" 이어붙이지 말 것.** header.jsp가 CSS 4개를 전 페이지에
   무조건 로드해서, 스코프 없는 `body{}` / `main{}` / `#id{}` 선택자가 하나라도 섞이면 사이트
   전체로 샌다. HANDOFF 3-5/3-6에서 크게 겪었고 3-37에서 또 3곳 재발했어.
   병합 직후 `grep -n "^body\s*{\|^main\s*{\|^#" style_user.css` 한 줄로 바로 확인 가능.
   `style_admin.css`가 이 원칙을 제대로 지킨 참고 사례야(전부 `.admin-xxx-page`로 스코프).
2) **`href="#"` placeholder 링크에 색을 입힐 땐 순수 클래스 선택자만 쓰지 말 것.**
   `default.css:22`의 `a:visited{color:#333}`(명시도 0,1,1)가 클래스 하나(0,1,0)를 이겨서 검게 나와.
   ID 스코프 등으로 명시도를 올릴 것. (PROJECT_AUDIT.md 잠재적 위험 19번)
3) **아이콘은 유니코드 글리프(★/♡) 대신 SVG로.** 환경에 따라 컬러 이모지로 렌더링돼서 CSS color를
   무시하거나 정렬이 어긋나. 헤더(`#site-header .icon-svg`)와 같은 스타일로 통일.
4) **화면 확인은 내가 해야 해.** 너한테는 브라우저/렌더링 도구가 없어서 정렬·색·간격 같은 픽셀
   단위 결과를 직접 못 봐. 추정으로 반영했으면 "추정이다"라고 분명히 말하고 나한테 확인을 요청해 줘.
   (실제로 이것 때문에 여러 번 헛돌았고, 마지막 원인은 내가 DevTools로 직접 찾았어.)
5) **테스트 데이터는 만들었으면 반드시 정리**(파일 + DB 양쪽). PowerShell에서 한글 문자열 `-like`
   필터가 조용히 실패한 적 있으니 **ID 기준으로 직접 삭제**할 것.
6) 변경 후엔 `mvnw compile` + 실행 중인 로컬 서버에 실제 요청으로 라이브 검증.
7) **git commit은 내가 직접 해.** 먼저 커밋하지 마.
8) 작업이 끝나면 `HANDOFF.md`에 **새 섹션(`3-42` 부터, 날짜 포함)** 으로 내용을 추가해 줘.
   문서 맨 위 "지금 상태 요약" 표도 같이 최신화할 것.
