1) **옛 페이지별 CSS를 "원본 그대로" 이어붙이지 말 것.** header.jsp가 CSS 4개를 전 페이지에
   무조건 로드해서, 스코프 없는 `body{}` / `main{}` / `#id{}` 선택자가 하나라도 섞이면 사이트
   전체로 샌다. 점검: grep -n "^body\s*{\|^main\s*{\|^#" style_user.css
2) **콤마로 나열된 CSS 셀렉터 목록을 부분 교체하지 말 것** (2026-09-02에 실제로 냄).
   `.input-area input,` + `.input-area select{...}` 에서 select 블록만 갈아끼웠더니
   앞 줄이 남아 **화살표가 input에도 붙었다.** 주석을 사이에 끼워도 CSS는 콤마 목록을 그대로
   이어 붙여 파싱한다. **공통 뼈대 / 개별 규칙으로 분리**할 것.
3) **브라우저가 자동으로 붙이는 상태를 hover처럼 다루지 말 것** (AUDIT 19·21·22번)
   - `href="#"`는 클릭 없이도 `:visited` → 순수 클래스 선택자로 색을 주면 밀린다
   - 클릭 요소의 강조는 `:focus`가 아니라 **`:focus-visible`** (뒤로가기 시 잔상 방지)
   - `hidden`으로 감출 요소가 `display`를 지정하는 클래스를 쓰면 `[hidden]`이 밀린다
4) **아이콘은 SVG로.** 공용 클래스가 `style.css`에 있음:
   `.icon-star`(fill) / `.icon-heart`(stroke, `.is-filled`로 채움) / `.icon-check` /
   `.icon-close` / `.icon-inline`(본문 속 아이콘용). 크기는 전부 em 기준.
5) **화면 확인은 내가 해야 해.** 너한테는 브라우저/렌더링 도구가 없어서 정렬·색·간격 같은
   픽셀 단위 결과를 직접 못 봐. 추정으로 반영했으면 "추정이다"라고 분명히 말하고 확인을 요청해 줘.
   조정이 필요한 값엔 `⚠️ 근사치라 화면 확인 필요` 주석을 달아두는 게 이 프로젝트 관례.
6) **병합 직후엔 "내가 최근에 바꾼 매퍼 문"이 살아있는지 확인할 것** (2026-09-02에 실제로 겪음).
   `ReviewMapper.xml`의 소프트 삭제가 병합으로 옛 하드 삭제 버전으로 되돌아가 있었는데,
   **컴파일도 통과하고 화면도 떠서 실제로 삭제를 눌러보기 전까지 안 드러났다.**
   되돌릴 땐 `git checkout`으로 통째로 덮지 말고, 상대 커밋이 뭘 바꿨는지 보고 **수동 병합**할 것.
7) **테스트 데이터는 만들었으면 반드시 정리**(파일 + DB 양쪽). PowerShell에서 한글 문자열
   `-like` 필터가 조용히 실패한 적 있으니 **ID 기준으로 직접 삭제**할 것.
   ※ `dummy_order_review.sql`로 넣은 더미는 예외 — 그 스크립트 맨 위 정리 블록이
     `dummy_`로 시작하는 계정만 지우므로 재실행으로 정리된다.
8) **주석은 짧게, 근거는 HANDOFF 번호로 참조.** 5줄짜리 설명 대신 "(HANDOFF 3-50 참고)" 형태.
9) 변경 후엔 `mvnw compile` + 실행 중인 로컬 서버에 실제 요청으로 라이브 검증.
   단 **브랜치를 크게 오간 뒤엔 `compile`이 아니라 `clean compile`** — 낡은 매퍼 XML이
   `target/classes`에 남아 MyBatis 기동을 깨뜨린다(3-45에서 실제로 겪음).
   ※ 내 로컬 서버는 IDE에서 띄운 인스턴스라 Claude 빌드가 안 붙을 수 있음. 그럴 땐
     `mvnw spring-boot:run -Dspring-boot.run.arguments=--server.port=8798` 로 별도 포트에
     띄워서 검증하고 끝나면 종료할 것.
10) **같은 금액·규칙을 서버와 화면이 각각 계산하게 두지 말 것** (AUDIT 25·26번, 2026-09-02)
    결제 금액이 서버는 "한 번에 곱하고 마지막에 반올림", 화면은 "단계마다 버림"이라
    **67% 조합에서 최대 2원 어긋나 있었다.** 검증에 안 쓰이는 값이라 조용히 다르게 결제됐다.
    어느 쪽이 정답인지(= 저장되는 값) 정하고 다른 쪽이 **반올림 시점·단위까지 그대로 흉내내게** 할 것.
    정책 상수(임계금액·수수료·최소단위)는 서버에서 화면으로 내려보낼 것 — 화면에 숫자를 직접 적지 말 것.
11) **파일명·뷰 이름을 고칠 땐 그 이름을 문자열로 쓰는 곳을 전부 찾을 것** (AUDIT 27번)
    JSP 파일명 오타를 고쳤는데 컨트롤러의 `return "order/userOderDelivery"` 한 줄이 안 따라와
    `/member/orderDelivery`가 404였다. **컴파일러가 못 잡고 그 화면을 열어봐야만 드러난다.**
    `grep -rn "<옛이름>"` 한 번이면 된다.
12) **git commit / push / 병합은 내가 직접 해.** 먼저 커밋하지 마.
13) 작업이 끝나면 `HANDOFF.md`에 **새 섹션(`3-63` 부터, 날짜 포함)** 으로 내용을 추가해 줘.
    문서 맨 위 "지금 상태 요약" 표와 목차도 같이 최신화할 것.
